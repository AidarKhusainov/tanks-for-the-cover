# Tanks for the Cover

Браузерный 2D-прототип игры про танк, защищающий базу. Основная механика — уничтожать противников в подходящих местах и использовать оставшиеся корпуса как баррикады либо разбирать их для ремонта базы, получения модуля или укрепления другого корпуса.

**Основная сборка (`index.html`)** — прототип 06 с четырьмя встроенными картами. Открой «Карты» и выбери «Магнитную доску», «Город», «Три подхода (тест)» или «Шлюз № 7». [Играть на GitHub Pages](https://aidarkhusainov.github.io/tanks-for-the-cover/). [Ранее опубликованная сборка](https://tank-magnetic-prototype.light-ash-3014.chatgpt.site/) может отличаться от текущего файла репозитория.

## Запуск

Скачай репозиторий и открой **`index.html`** в настольном браузере. Игра полностью автономная: не нужны сервер, Java, npm или внешние ресурсы.

Через Git:

```bash
git clone https://github.com/AidarKhusainov/tanks-for-the-cover.git
cd tanks-for-the-cover
```

Открой `index.html` двойным щелчком. Ссылка «Скачать для игры офлайн» на странице, открытой через HTTP(S), сохраняет HTML под именем `tank-prototype.html`. Для проверки скачивания можно запустить `python3 -m http.server 8765 --bind 127.0.0.1` и открыть [локальную страницу](http://127.0.0.1:8765/index.html). Уже открытый локальный HTML можно скопировать средствами ОС.

## Редактор карт

Чтобы изменить «Шлюз № 7», открой в редакторе [JSON этой карты](maps/sluice-7.json) через «Загрузить JSON». Нажми «Играть на этой карте», чтобы проверить свои изменения.

[Открыть редактор онлайн](https://aidarkhusainov.github.io/tanks-for-the-cover/tools/map-editor.html) или скачай репозиторий и открой [файл редактора](tools/map-editor.html). Он также доступен через кнопку «Редактор карт» в игре и в выборе карты. Это отдельный автономный HTML-инструмент для карты 28 × 18: перемещение и изменение размеров препятствий, настройка спавна, базы и позиции игрока, геометрический предпросмотр маршрута и импорт/экспорт JSON.

1. Построй карту и исправь отмеченные ошибки геометрии. Нужны один спавн, одна база и позиция игрока размером 1 × 1.
2. Нажми **«Играть на этой карте»**: соседняя вкладка откроет «Мою карту (тест)» в настоящей игре. Снимок передаётся в ссылке; перезагрузка игры оставляет ту же карту.
3. Начни волну. Для проверки используются прежние восемь волн / 66 противников через спавн A с интервалом не меньше 2,5 с. Геометрический маршрут редактора остаётся приблизительным; окончательное поведение определяет игровое ядро.
4. Нажми **«К редактированию»**, измени схему и снова запусти тест. Для успешно сохранённого запуска из редактора возврат использует последний локальный черновик, включая более свежие изменения в исходной вкладке. Карта, импортированная непосредственно в игру, возвращает собственный снимок.

Черновик автоматически сохраняется в этом браузере, если доступно локальное хранилище. Текущая схема также обновляется в адресной строке редактора, поэтому перезагрузка сохраняет изменения после импорта. При запрете хранилища редактор показывает предупреждение: скачай JSON перед закрытием. Возврат из игры в таком режиме восстанавливает снимок тестируемой карты. Автосохранение не заменяет резервную копию: кнопки «Скачать JSON» и «Загрузить JSON» позволяют переносить черновик. В самой игре JSON формата `tanks-map-editor` версии 1 загружается через «Карты» → «Загрузить карту JSON».

Игра проверяет формат, размеры, пересечения, свободные стартовые позиции и возможность добраться до огневой позиции у базы. Приблизительный маршрут до самой базы в редакторе может отсутствовать, даже если доступна огневая позиция: это предупреждение, тест разрешён. Неверная карта показывает ошибку со ссылкой на исправление и не мешает запуску штатных карт. Возвращение игрока использует свободное место около заданной стартовой позиции; защищённая ниша автоматически не строится. Баланс пользовательской карты не проверен.

Для полного цикла офлайн нужны оба файла с сохранёнными путями: `index.html` и `tools/map-editor.html` из репозитория. Самостоятельно скачанный игровой HTML по-прежнему работает без редактора; пользовательскую карту можно загрузить в него из отдельного JSON. Сервер и внешние зависимости не требуются.

## Карты основной игры

На всех четырёх картах кампания длится восемь волн с одинаковым составом противников. На «Магнитной доске» и в «Городе» группы атакуют с трёх входов. На картах «Три подхода (тест)» и «Шлюз № 7» все 66 противников выходят через вход A с интервалом не меньше 2,5 с. Выбор карты начинает новую попытку и сбрасывает HP, корпуса, модуль и действия подготовки.

| Карта | Схема обороны |
| --- | --- |
| Магнитная доска | База снизу по центру. Одна латунная метка в горловине A и две рядом на широком входе B показывают, где оставить корпуса. На C короткий путь тоже можно закрыть одним корпусом. |
| Город | База в западном квартале. Из погрузочного двора у восточного входа C можно остановить средний танк штатным орудием. Следующая группа может уйти на южную улицу. Для защиты B придётся выехать из двора. На B два последовательных рубежа, каждый закрывается одним корпусом. |
| Три подхода (тест) | Один вход A слева, база справа снизу. Центральный проезд шириной в полтора корпуса даёт быстрый путь. Корпус в центре может направить следующих врагов наверх, а второй на верхнем пути — вниз. Точка возвращения игрока открыта. |
| Шлюз № 7 | Противники огибают машинный зал с севера. Корпус в узкой северной створке может направить их через южный док. Между островом и диспетчерской есть поперечный проход для смены фланга. |

Плановые старты зависят от карты и известны до начала волны. Во время боя предупреждение отличает отсчёт от ожидания занятого входа. [Схемы, измерения и воспроизведение проверок двух исходных карт](docs/two-map-verification.md).

[Проверка текущего ИИ и поздних волн](docs/ai-firing-self-defense-verification.md) описывает исправление огневой очереди, ответный огонь и обновлённые городские тайминги.

## Управление

Управление, механики и журнал ниже описаны для основной сборки `index.html`.

- `WASD` — движение; мышь — прицеливание.
- Удержание левой кнопки мыши — огонь.
- В подготовке щёлкни по корпусу для разбора, сохранения или укрепления. Для укрепления выбери донора, нажми «Укрепить другой корпус», выбери цель на поле и подтверди расход.
- Наведи указатель на действие подготовки или перейди к нему клавишей Tab. На поле появятся метки расходуемого корпуса и цели. Отмена показывает корпуса и позицию танка, которые она восстановит.
- `Ctrl+Z` — отмена последнего действия подготовки, `Enter` — начать волну, `Esc` — пауза или выход из выбора цели укрепления.

## Что реализовано

Лёгкие противники ненадолго преследуют игрока, средние давят на базу. Средний и тяжёлый отвечают на направленный в них снаряд или недавнее попадание, если игрок доступен, удерживая место боя. Ответный огонь приоритетнее расчистки; тяжёлый сохраняет быстрое достижимое добивание базы раньше вероятной гибели. Передний танк при свободном выходе освобождает место для стрелков позади. Лёгкие и средние могут повторно уклоняться от летящих снарядов игрока, если их обычный путь ведёт под попадание и сбоку есть место. Для точного размещения среднего корпуса можно целиться в центр танка. В подготовке видны порядок танков и время старта групп ближайшей атаки. Кнопка «Кампания» открывает расписание всех восьми волн с отметкой финала.

Средние и тяжёлые танки оставляют корпуса, которые меняют движение и огонь. В подготовке корпус можно оставить, разобрать для ремонта базы, обменять на модуль или потратить на укрепление другого корпуса. Танки сравнивают время обхода и расчистки, делят свободные огневые позиции и уступают прострел союзнику в узком проходе. Прогноз по входу и типу показывает оценочное время и путь до огня по базе или цели первого пролома. На двух исходных картах танк игрока возрождается в защищённой нише. На «Трёх подходах» точка возвращения открыта, на «Шлюзе № 7» игрок возвращается в ремонтный карман.

Первый появившийся корпус отмечается на поле, а в первой подготовке с пригодным корпусом подсказка объясняет варианты действий и срок службы. Перечёркнутый корпус у противника показывает, что его центр ещё в зоне появления. Экран поражения сообщает, какое попадание уничтожило базу, и предлагает начать заново.

Средний корпус служит одну следующую волну и даёт до 25 HP ремонта, тяжёлый — две волны и до 45 HP. Из среднего корпуса можно взять двигатель (5 ед/с) или удлинённый ствол (дальность 6,75 вместо 6). Тяжёлый даёт броню (90 HP). В танке один слот. Укрепление восстанавливает до половины максимальной прочности цели, добавляет одну волну службы и отмечается стрелкой ↑ у корпуса. Каждую цель можно укрепить один раз. Укрепление, смена модуля и ремонт отменяются в обратном порядке, с возвратом корпусов и танка на позицию перед действием. При гибели модуль сохраняется, при новой попытке слот пуст.

Обсуждавшиеся [взрыв боеукладки](docs/ideas/ammo-rack-detonation.md) и отказ от защищённой ниши **не реализованы**.

## Журнал попытки для плейтеста

Кнопка «Скачать журнал JSON» под полем, в меню паузы и на экране результата сохраняет `tanks-<mapId>-v<mapVersion>-attempt.json`. Экспорт доступен офлайн во время попытки и после её завершения, пока не начата новая. Скачивание сохраняет снимок, а запись продолжается. Новая попытка начинает свой журнал в памяти.

Формат JSON, версия 1:

- `formatVersion`, `buildId`, `attemptNumber` — версия формата, идентификатор сборки и номер попытки с открытия страницы. При смене карты начинается новая попытка. Для сравнения журналов учитывай карту и конфигурацию.
- `configuration` — параметры на старте попытки. `game` включает `mapId`, `mapVersion`, геометрию, входы, параметры противников и плановые группы волн. Позиции даны в координатах поля, ось Y направлена вниз.
- `current` — состояние на момент экспорта с фазой, волной, HP базы, состоянием танка, корпусами и фактическими счётчиками симуляции.
- `events` — события в порядке `sequence`, начиная с 1. Номер `wave` начинается с 1. `preparationSeconds` и `battleSeconds` — накопленное время шагов симуляции в подготовке и в бою. Долёт последних снарядов входит в бой. Пауза, справка и открытая сводка кампании исключены. Длительность волны можно получить по разнице `battleSeconds` у `wave_start` и `wave_end`, а время отсутствия игрока — между `player_death` и `player_return` либо концом попытки.
- `wave_start` и `wave_end` содержат состояние базы, танка и корпусов. `wave_end.outcome` равен `cleared` или `lost`, а `attempt_end.outcome` — `won` или `lost`. Снимок конца волны сохраняется до смены номера волны и восстановления танка.
- В состоянии игрока `module` и `weaponRange` показывают фактическую конфигурацию. События решений ИИ помогают сопоставить выбранный путь, огневую позицию и смену приоритета тяжёлого.
- `wreck_created` и `wreck_removed` содержат снимок корпуса с устойчивым в пределах попытки `id`, типом, координатами, прочностью и последней волной службы. Причины удаления — `salvaged`, `destroyed_by_player`, `destroyed_by_enemy`, `expired`.
- `repair`, `module_change` и `reinforce` содержат фактический результат действия. `actionSequence` у расхода корпуса и у `undo` указывает на исходное действие. Отмена дописывает восстановленные состояния в конец журнала.

## Проверки

Для автоматических тестов симуляции нужен Node.js 20 или новее:

```bash
npm test
```

Тесты используют встроенный `node:test` без внешних зависимостей. Общий загрузчик исполняет первые два JS-блока `index.html` с данными карты и ядром симуляции. Набор покрывает:

- движение, столкновения, защиту и выход из ниши, проходы A/B/C, обходы и заторы;
- выстрелы и попадания, выбор цели и готовность оружия, погоню лёгкого танка;
- границы зон и очередь появления, соответствие восьми волн таблице PDD, завершение волн и долёт снарядов, срок службы корпусов, возвращение игрока, паузу и сброс;
- ремонт базы, параметры и замену модулей, укрепление за донора, смешанную цепочку отмены и сохранение модуля при возвращении танка;
- выбор пролома или обхода по времени, последовательные преграды, прострелы корпуса, базы и игрока, переключение тяжёлого, маршрут и его пересчёт.

Общий `npm test` также проверяет воспроизводимость HTML и геометрию обеих городских сборок, сохранение кампании 2D-карты и симуляцию 3D-версии.

GitHub Actions запускает `npm test` на Node.js 22 при push в `master` и при pull request. Контрольные сцены #33 и команды повтора описаны в [проверках общих правил](docs/shared-combat-checks.md). Прежние замеры хранятся в [отчёте приёмки прототипа 06](docs/prototype-acceptance.md). Баланс и интерес проверяются в плейтесте [#14](https://github.com/AidarKhusainov/tanks-for-the-cover/issues/14).

## Структура

- `index.html` — полный самодостаточный игровой прототип: разметка, стили, сценарии, логика симуляции и интерфейс.
- `experiments/warm-town-2d/` — автономная 2D-карта, её исходники и проверки.
- `experiments/warm-town-3d/` — самостоятельная 3D-версия, её исходники, автономный HTML и проверки.
- `tests/` — smoke-тесты, регрессионные сценарии симуляции и общий загрузчик ядра.
- `package.json` — команда тестирования, не требуется для игры.
- `.github/workflows/ci.yml` — автоматическая проверка.
