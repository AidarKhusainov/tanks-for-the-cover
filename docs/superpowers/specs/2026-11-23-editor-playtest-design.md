# Редактор и немедленный плейтест

Пользователь одобрил предложенный цикл: редактор → «Играть на этой карте» в соседней вкладке → возвращение к редактированию. Цель — быстро сравнивать схемы без ручного переноса JSON в исходники.

## Подход

Выбран отдельный редактор: существующий автономный HTML сохраняется, игра остаётся автономным `index.html`. Встраивание редактора в игровой экран потребовало бы лишней перестройки интерфейса. Передача только через localStorage зависела бы от разрешений браузера; поэтому снимок карты передаётся в URL fragment, который работает и без сервера. Черновик дополнительно сохраняется локально; при недоступном хранилище остаются JSON и ссылка с картой.

## Поведение

- В игре и выборе карты есть вход в редактор и загрузка JSON; пользовательская карта появляется отдельным вариантом без изменения штатных карт.
- Редактор открывает текущую геометрию в соседней вкладке. Повторное тестирование передаёт новый снимок; перезагрузка игры сохраняет его.
- Возврат из игры восстанавливает последний сохранённый черновик, а при недоступном localStorage — тестируемый снимок из ссылки.
- Возобновление локального черновика включается только для успешно сохранённого запуска из редактора. Карта, импортированная прямо в игру, возвращает собственный снимок. Лимит текста JSON согласован с собственным экспортом (600 000 символов/байтов при чтении файла); ограничения схемы применяются отдельно.
- Один спавн A, существующие восемь волн / 66 противников и интервал 2,5 с. Боевые правила не меняются. Область возврата ищется около выбранной позиции игрока с существующей проверкой свободного места.
- Перед запуском проверяются формат `tanks-map-editor` v1, поле 28 × 18, не более 300 объектов, конечные координаты, уникальные ID, ровно один спавн/база/игрок, границы и пересечения. Игрок имеет диаметр 1; спавн вмещает танк. Игра проверяет свободные начальные позиции и достижимость огня по базе своим ядром.
- Ошибки карты видны в интерфейсе и не прерывают работу обычной игры. Черновик, импорт/экспорт JSON и undo/redo сохраняются. Новых зависимостей, сервера и изменений механик нет.
- Приблизительная недостижимость самой базы в редакторе — предупреждение, не запрет теста: игровой ИИ может найти огневую позицию. При отказе игры снимок можно вернуть в редактор для исправления. Добавление/дублирование не превышает ограничения схемы, автосохранение не заменяет валидную копию структурно нечитаемыми данными.
- Редактор синхронизирует текущий снимок в адресной строке после изменения: перезагрузка не возвращает первоначальный импорт, даже при отказе хранилища. Ссылка исправления показывается только для читаемого формата редактора; повреждённый JSON/чужая версия дают сообщение об ошибке.

## Приёмка

Автотесты проверяют перенос координат, запуск противника, геометрию, состав кампании, возвращение игрока, отклонение повреждённых карт. Браузер: изменить стену → тест → начать волну → вернуться → изменить ещё раз → повторный тест; перезагрузка, импорт JSON, ошибочная карта, заблокированное хранилище, автономный запуск. Финальный `npm test`, независимое ревью, CI и проверка GitHub Pages после разрешённой публикации.
